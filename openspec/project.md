# TitanChain 项目指南

## 项目目标
TitanChain 是一条高性能区块链网络，专注于构建下一代去中心化基础设施。项目目标包括：

- **高性能区块链主网**：实现 20 万 TPS 的超高吞吐量、低于 100ms 的极低延迟
- **零手续费体验**：为交易所批量交易提供 0-gas 费机制
- **去中心化治理**：108 个验证节点 + 2000 个候补节点的 PoS 共识机制
- **完整生态系统**：包含区块链浏览器、质押系统、钱包集成等核心模块
- **交易所集成**：支持全链统一订单簿和流动性共享

## 技术栈

### 前端技术
- **React 18** + **TypeScript** - 现代化前端框架
- **Vite** - 快速构建工具和开发服务器
- **TailwindCSS** - 实用优先的 CSS 框架
- **Zustand** - 轻量级状态管理
- **React Query** - 数据获取和缓存
- **React Router** - 客户端路由
- **Recharts** - 数据可视化图表

### 后端技术
- **Node.js** + **Express** - 服务端运行时和 Web 框架
- **TypeScript** - 类型安全的 JavaScript
- **PostgreSQL** - 主数据库
- **Redis** - 缓存和会话存储
- **Socket.io** - 实时通信
- **WebSocket** - P2P 网络通信

### 区块链技术
- **自研 PoS 共识机制** - 108 验证节点共识
- **EVM 兼容** - 支持 Solidity 智能合约
- **零 Gas 引擎** - 交易所批量交易免费机制
- **高性能处理器** - 支持 20 万 TPS 目标
- **VRF 随机选择器** - 安全的验证节点选举

### 钱包集成
- **Ethers.js** - 以太坊交互库
- **Wagmi** - React Hooks for Ethereum
- **Web3Modal** - 多钱包连接支持
- **WalletConnect** - 去中心化钱包连接协议

### 开发工具
- **ESLint** + **TypeScript ESLint** - 代码质量检查
- **Nodemon** - 开发时自动重启
- **Concurrently** - 并行运行多个命令
- **TSX** - TypeScript 执行器

## 项目规范

### 代码风格
- **TypeScript 严格模式**：使用 TypeScript 进行类型安全开发
- **ESLint 配置**：遵循 React Hooks 和 TypeScript 最佳实践
- **模块化架构**：按功能模块组织代码结构
- **路径别名**：使用 `@/*` 指向 `src/*` 目录
- **命名规范**：
  - 文件名使用 kebab-case（如 `validator-manager.ts`）
  - 组件名使用 PascalCase
  - 变量和函数使用 camelCase
  - 常量使用 UPPER_SNAKE_CASE

### 架构模式
- **分层架构**：
  - `src/` - 前端 React 应用
  - `api/` - 后端 API 服务
  - `blockchain/` - 区块链核心逻辑
  - `shared/` - 共享类型和工具
- **模块化设计**：每个功能模块独立，便于维护和扩展
- **类型驱动开发**：所有接口和数据结构都有完整的 TypeScript 类型定义
- **事件驱动架构**：使用 Socket.io 实现实时数据同步
- **微服务思想**：区块链节点、API 服务、前端应用可独立部署

### 测试策略
- **模块完成后必须测试通过**：每完成一个模块必须先测试通过后再进行下一个模块开发
- **综合功能测试**：使用 `comprehensive-test.js` 验证所有核心功能
- **性能安全测试**：使用 `test-performance-security.js` 验证性能和安全机制
- **交易测试**：使用 `test-transactions.js` 进行交易功能测试
- **PoS 和零 Gas 测试**：使用 `test-pos-zerogas.js` 验证共识和费用机制
- **自适应限流测试**：使用 `scripts/test-adaptive-rate-limit.ts` 验证限流机制

### Git 工作流
- **功能分支开发**：每个新功能在独立分支开发
- **代码审查**：重要功能需要代码审查
- **提交规范**：使用清晰的提交信息描述变更
- **版本管理**：使用语义化版本号
- **忽略文件**：完整的 `.gitignore` 配置，排除构建产物和敏感文件

## 领域知识

### 区块链核心概念
- **PoS 共识机制**：权益证明，验证节点通过质押 TTN 代币参与共识
- **验证节点管理**：108 个活跃验证节点 + 2000 个候补节点
- **零 Gas 机制**：交易所批量交易享受免费上链服务
- **高性能处理**：目标 20 万 TPS，实际测试中需要适应系统限制
- **安全防护**：51% 攻击防护、违规检测、VRF 随机选择

### 业务流程
- **用户交易流程**：钱包连接 → 交易签名 → 零 Gas 确认 → 区块链浏览器查询
- **验证节点流程**：候补节点质押 → 排名竞争 → 当选验证 → 性能监控 → 奖励分配
- **交易所集成**：批量交易 → 0-gas 上链 → 数据验证 → 流动性共享

### 技术特色
- **自适应限流**：根据网络负载动态调整交易处理速度
- **微批调度**：优化交易批次处理，提高网络效率
- **实时监控**：完整的性能指标和网络健康度监控
- **多钱包支持**：兼容主流以太坊钱包生态

## 重要约束

### 技术约束
- **macOS 开发环境**：项目在 macOS 系统上开发和测试
- **性能目标**：20 万 TPS 目标需要在实际硬件限制下平衡实现
- **测试模式限制**：`TESTING_MODE` 下某些限流机制被禁用
- **内存和 CPU 限制**：高性能处理需要考虑系统资源限制

### 业务约束
- **去中心化要求**：最大限度保持去中心化思维
- **安全优先**：安全性和性能的平衡，安全性优先
- **用户体验**：零手续费体验不能影响网络安全性
- **监管合规**：需要考虑不同地区的监管要求

### 开发约束
- **模块化开发**：每个模块必须独立测试通过
- **类型安全**：所有代码必须通过 TypeScript 类型检查
- **代码质量**：必须通过 ESLint 检查
- **测试覆盖**：核心功能必须有对应的测试脚本
