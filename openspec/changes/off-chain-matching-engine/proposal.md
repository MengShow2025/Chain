# 验证节点端链下撮合引擎实现提案

## 变更ID
`off-chain-matching-engine-v1`

## 变更概述
实现验证节点端的链下撮合引擎系统，包括50-100ms微批处理、验证层并行化和消息总线架构，以提升TitanChain的交易处理性能和可扩展性。

## 业务背景
当前TitanChain虽然已实现200k TPS的高性能处理，但在面对更大规模的交易量时，需要引入链下撮合机制来进一步提升性能。通过将撮合逻辑移至链下，并配合验证层并行化，可以实现更高的吞吐量和更低的延迟。

## 技术目标
- **性能提升**：支持更高的交易吞吐量（目标500k+ TPS）
- **延迟优化**：微批处理延迟控制在50-100ms内
- **可扩展性**：支持水平扩展的验证节点架构
- **安全保障**：确定性重放和挑战机制确保安全性

## 架构设计

### 1. 链下撮合引擎
```
订单流入 → 微批聚合(50-100ms) → 撮合处理 → BatchCommit生成 → 验证层提交
```

**核心组件**：
- **MicroBatchProcessor**：微批处理器，聚合50-100ms内的订单
- **OffChainMatcher**：链下撮合引擎，执行订单匹配逻辑
- **BatchCommitGenerator**：生成包含Merkle根和CID的批次提交
- **DeterministicReplayer**：确定性重放器，支持挑战验证

### 2. 验证层并行化
```
BatchCommit → 并发下载 → 顺序重放 → 分层验证(L0→L1→L2→L3) → 挑战窗口(2s)
```

**分层验证架构**：
- **L0层**：基础数据完整性验证
- **L1层**：订单匹配逻辑验证
- **L2层**：状态转换验证
- **L3层**：最终一致性验证

### 3. 消息总线系统
```
入口服务 → MQ/流系统 → 撮合引擎 → MQ/流系统 → 验证层 → DA存储
```

**支持的消息系统**：
- **NATS**：轻量级，低延迟（推荐用于微批处理）
- **Kafka**：高吞吐量，持久化（推荐用于审计日志）
- **RabbitMQ**：可靠性，复杂路由（推荐用于错误处理）
